# 创作中心音视频来源读取

日期：2026-08-02  
状态：已确认

## 目标

让创作中心的结构化生成器正确消费文档模块中选中的音频、视频和 `.media.md` 媒体引用，而不是把媒体二进制交给 `document_read` 或静默忽略。

## 路由

- PDF、Word、Excel、PPT 继续优先通过 `document_read` 读取。
- 文本、Markdown、代码、CSV 等继续走受限文本读取。
- 音频、视频与 `.media.md` 通过媒体模块的已发布解析结果读取，相当于 `media_read` 的同一数据语义；不读取媒体二进制。

## 证据策略

媒体来源按以下顺序组成受限证据：

1. 读取 metadata，确认媒体类型、解析状态和可用模式。
2. 有章节时优先使用章节标题与摘要。
3. 有主题时，按主题搜索转录命中及相邻上下文；无主题或无命中时读取有限的转录片段。
4. 保留时间戳和覆盖范围，不把局部片段称为完整观看/收听。

媒体来源通过已保存的 `mediaId` 或文档文件的活跃媒体链接解析。前端生成来源判定将音视频和 `.media.md` 视为合法来源。

## 未解析媒体

不在生成任务中隐式发起转录、下载或关键帧提取，避免绕过现有 `mediaAction` 的确认与费用控制。

- 未解析媒体与其他可读资料同时存在时：跳过该媒体并在任务进度中明确说明。
- 未解析媒体是唯一来源且用户未填写主题时：任务在模型调用前失败，提示先在文档模块完成媒体解析。
- 用户已填写主题时：任务可继续，但明确不把未解析媒体视为依据。

## 验证

做定向检查：类型路由、已解析章节/转录证据、未解析媒体提示、媒体作为唯一来源的阻止逻辑、普通文档与文本的既有路径不回归。不会运行完整 build。

# K12 四学科学习助手设计

## 目标

首期新增四个独立的对话型学习 Agent：数学学习助手、英语学习助手、物理学习助手和化学学习助手。

每个 Agent 提供本学科的学习路径、概念讲解、题目训练、错因分析、资料处理和可视化选择；它们不是通用学习助手的改名副本。四者复用已有的学习闭环能力，并通过少量专项 Skill 补齐学科工作流。

长期方向是覆盖 12 学科，但本期不创建另外 8 个空壳 Agent。

## 不做范围

- 不新增学习档案、K12 Profile、数据库表或设置页表单。
- 不新增中考、高考、地区分数线、志愿或考试模式。
- 不推断用户年龄、年级、学校、地区、教材或考试身份。
- 不把 AI 生成的作文分数、实验结论或练习难度冒充官方标准。

## 记忆使用

用户自行在现有“设置 > 记忆管理”中维护长期信息，例如年级、地区、教材版本、课程、学习目标和偏好。当前运行时会将保存的语义记忆写入 Agent 的系统上下文；这不是按学科或问题预先筛选的注入机制。

每个学科 Agent 的规则：

1. 优先使用当前对话和已有记忆中的明确资料。
2. 只采用与当前学科问题直接相关的记忆，不主动提及、推断或暴露无关的个人信息。
3. 当前任务需要年级、教材或地区而信息缺失时，先完成不依赖该信息的部分。
4. 用一条简短提示说明用户可在“设置 > 记忆管理”补充长期信息，也可直接在当前对话提供。
5. 不因为记忆缺失阻塞普通答疑，不自动创建新的学习档案或猜测用户信息。

## Agent 结构

四个 Agent 均采用已有内置 Agent 目录规范：独立 `config.json`、独立 `PROMPT.md`、独立名称、图标、版本、工具和 Skill 列表。

共享能力按需绑定：

- `concept-explainer`、`socratic-tutor`、`feynman-learning-coach`
- `knowledge-organize`、`practice-quiz`、`error-analysis`
- `review-plan`、`exam-prep`、`mock-exam`、`flashcard-generator`、`note-skill`
- `learning-visualization-skill`、`document_read`、`vision_analyze`、`calculator`

只有确实生成或校验可视化文件的学科 Agent 才保留 `exec_command`；命令仍受产品审批，不能作为普通答疑的默认路径。

## 数学学习助手

数学学习助手以代数、函数、几何、概率统计和题目推理为主。

- 复用：`math-explainer`、`edu-solid-geometry`、`edu-analytic-geometry`、`geometry-assistant`。
- 新增：`k12-math-learning`，统一年级化讲解、题型拆解、条件/结论检查、变式训练和错因分类。
- 不把一次做对视为掌握；以用户解题过程、提示次数和变式结果决定后续难度。

## 英语学习助手

英语学习助手覆盖词汇、语法、阅读、写作和翻译的 K12 学习场景。

- 新增：`k12-english-learning`，处理词汇复习、句法错误、阅读证据定位、写作修改和翻译反馈。
- 复用：`practice-quiz`、`error-analysis`、`flashcard-generator`、`review-plan`。
- 不绑定大学英语四、六级专用 `cet-skill`；不把模型的写作反馈表述为中高考官方评分。

## 物理学习助手

物理学习助手覆盖概念、受力/电路/光路示意、公式建模、单位检查、实验理解和计算题。

- 新增：`k12-physics-learning`，处理题目条件抽取、物理量与单位校验、建模步骤、实验变量和常见误区。
- 复用：`math-explainer`、`learning-visualization-skill`、`calculator`、`error-analysis`。
- 只有运动、受力、电学等确实需要动态表示时才生成可视化文件。

## 化学学习助手

化学学习助手覆盖方程式、反应分类、微观过程、实验现象、物质性质和基础计算。

- 新增：`k12-chemistry-learning`，处理方程式、现象与条件、实验安全边界、守恒/物质的量计算和错因分析。
- 复用：`edu-chem-reaction`、`learning-visualization-skill`、`calculator`、`error-analysis`。
- `edu-chem-reaction` 只用于已支持或可校验的微观反应演示，不能承担反应预测或危险实验指导。

## 交互规则

1. 用户选定某学科 Agent 后，该 Agent 优先按本学科目标、术语和题型组织回答。
2. 用户提供教材、题目、错题或资料时，先读资料，再把用户资料与通用知识区分开。
3. 用户只问一个即时问题时直接回答，不强制制定计划、写入记忆或生成文件。
4. 用户提出“练习、错题、复习、可视化、资料整理”时，选择对应的共享或专项 Skill。
5. 用户明确要求长期记住的信息时，遵循现有记忆管理能力；本期不修改其数据模型。

## 验证

- 四个 Agent config JSON 可解析，ID、目录和 Prompt 路由一致。
- 每个 Agent 的 tools、permissions 与绑定 Skill 的真实需求一致。
- 每个新增 Skill 有 `config.json`、`SKILL.md`、准确的工具/输出声明和 2-3 个 eval 场景。
- 使用每科至少一个真实问题验证：即时答疑、用户资料、练习/错因和一个专项产物或降级路径。
- 验证记忆缺失时 Agent 仍能工作，并仅给出简短的记忆管理提示。
- 验证已有记忆中的明确年级或教材信息能影响当前 Agent 的回答；即使无关记忆也在系统上下文中，Agent 也不会主动引用或暴露它。

## 后续扩展

生物、历史、地理、政治等学科以后沿用相同目录和质量标准加入。只有出现稳定的学科专属需求、资料形式或训练闭环时，才创建对应 Agent 和 Skill。

## 能力覆盖补充

### 学习链路与已有能力

四个 Agent 的目标是覆盖学习者当前的完整请求，而不是只回答学科问题。已有共享 Skill 按意图复用：

- 即时答疑、提示和分步推导：学科专项 Skill 与 `concept-explainer`、`socratic-tutor`、`feynman-learning-coach`。
- 教材、讲义、试卷、作业和截图：`document_read`、`vision_analyze` 与用户资料优先规则。
- 针对性练习、批改和错因复盘：`practice-quiz`、`error-analysis`。
- 复习安排、考前梳理、限时模拟、闪卡和笔记：`review-plan`、`exam-prep`、`mock-exam`、`flashcard-generator`、`note-skill`，且都只在用户明确提出相应目标时使用。
- 外部资料核验：`mcp:exa`，仅由当前问题的资料缺失、冲突、时效性或用户明确请求触发。

数学、物理和化学额外绑定 `exam2knowledge`，只用于一组用户提供的错题、试卷或可核验公开样题的考点归纳、解题模式和错因聚类。它的“高频”只能表示当前样本或可核验资料中的证据，不能变成对地区真题、考试命题或升学结果的预测。英语不绑定它：英语的阅读证据、写作反馈和题型训练由英语专项 Skill 与共享练习/模拟 Skill 处理。

不绑定 `study-companion-en`、`quiz-generator` 或 `exam-simulator`。它们分别会重复会话编排、练习生成和模拟卷工作流，且前者的默认会话/考试范围与本期 K12 边界不完全一致；现有的学科专项与共享 Skill 已有更明确的权限和产物约束。

### 可视化路由

可视化是帮助理解、订正或复习的可选手段，不是普通答疑的默认产物。所有学科先使用文字、KaTeX、表格或必要的简图；只有空间关系、变量变化、证据结构或微观过程本身是推理关键，或用户明确要求可视化产物时，才调用下列 Skill。需要文件或命令的路径仍须通过产品审批；没有必要时不生成文件。

| 学科 | 适合可视化的需求 | 首选路由 | 关键限制 |
| --- | --- | --- | --- |
| 数学 | 函数与参数变化、坐标/解析几何、平面或立体几何、概率统计数据、证明条件关系 | `math-explainer`、`edu-analytic-geometry`、`edu-solid-geometry`、`geometry-assistant`、`learning-visualization-skill` | 图形只表达题目已给或已推导的条件；不能从不清晰图片补造点、边、比例或结论。 |
| 英语 | 句子结构、阅读证据链、段落论证、写作前后对照、词汇关系 | 先用行内标注/对照表；用户明确需要可复习的图或页面时用 `learning-visualization-skill` | 普通语法和阅读答疑不生成文件；不能把改写或图示当成原文证据。 |
| 物理 | 受力、运动图像、电路状态、光路、波动、能量/动量关系、实验数据与误差 | `concept-visualization-generator`、`learning-visualization-skill`，变量随时间变化时可用 `math-explainer` | 图示必须标出研究对象、方向、单位和模型假设；装置和电路标注不清时先请求补充。 |
| 化学 | 周期性、原子/成键/构型、粒子守恒、计量与浓度、滴定或装置与现象对应 | `concept-visualization-generator`、`learning-visualization-skill` | 反应的分子动画只交给 `edu-chem-reaction`，且反应必须已支持或可被 kernel 校验；不预测未知产物或危险条件。 |

### 验证补充

每科保持三个可执行 eval 场景，合计覆盖：普通答疑不生成文件、用户资料或图像的来源边界、学科专项可视化或评估路由。数学、物理和化学另验证批量题目/试卷进入 `exam2knowledge` 时只做基于样本的归纳，不声称官方高频或押题。验证脚本还应检查该 Skill 只绑定到三门 STEM Agent，并且不引入新的工具权限或依赖安装。

## 听力资料与轻量入口补充

英语学习助手增加只读 `media_read`，仅处理当前运行已经授权且系统已解析的音视频。它先读取媒体元数据，再按学习任务读取转录、章节、检索命中上下文或必要关键帧，可用于听力材料定位、精听/听写、对话理解、基于文本证据的听力题讲解，以及基于转录内容的口头表达反馈。

`media_read` 不能解析、下载、截取或创建音视频，也不能让模型可靠评估发音、音色、重音、语调或口语分数。英语 Agent 必须明确这类边界；未提供授权媒体、转录不全或音频质量无法核验时，转为文本材料、用户转写或练习脚本，不伪造听力证据或发音结论。

四个 Agent 在用户请求过于宽泛、且没有给出明确任务时，提供一个轻量选择入口，例如“先讲解、带我做、出练习、复盘错题、安排复习”。用户已明确问题、答案形式或目标时，直接完成当前任务，不能用模式选择替代答疑、强制建立计划或强迫用户补充档案。

英语的三个 eval 场景更新为：普通语言答疑、基于原文证据的可视化、已授权听力材料的转录定位与隐藏答案练习。验证脚本检查 `media_read` 同时出现在英语 Agent 和英语专项 Skill 的工具声明中，并检查 Prompt 明确禁止伪造发音评分。

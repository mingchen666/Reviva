# 获取模型时配置能力

## 目标

在模型设置的“获取模型列表”弹窗中，让用户在添加前直接确认或修改每个选中模型的能力。无需先添加模型，再进入编辑弹窗。

## 交互

- 保持现有 `MsModal`、搜索框、模型行、复选框、能力标签、底部操作区的视觉和尺寸。
- 未选中模型继续显示现有的紧凑信息：模型 ID、服务端返回的启用能力和最大输出。
- 用户勾选一个未添加的模型时，该行下方展开能力标签；取消勾选时收起。
- 展开区只显示五个现有能力标签：工具、视觉、搜索、向量、重排序。标签点击仅切换自身状态，不影响该行的勾选状态。
- 不增加解释文案、二级弹窗、侧栏或额外确认步骤。
- 已添加模型保持禁用状态，不能展开或修改。
- “添加选中”使用用户在展开区最后确认的能力值写入 provider；未被用户改动的模型保留获取接口返回的能力值。

## 数据与保存

- 为获取弹窗维护按模型 ID 索引的能力草稿，打开弹窗时从 `fetchedModels` 深拷贝初始化。
- 添加时从草稿覆盖所选模型的 `capabilities`，继续调用既有 `settingsStore.addFetchedModels`。
- 弹窗关闭或下次获取时丢弃草稿；已入库模型仍可使用既有编辑入口修改能力。

## 验证

- 勾选、取消勾选、多选模型时，展开状态和数量正确。
- 点击能力标签不会改变模型选中状态，添加后配置值准确保存。
- 已添加模型不可交互。
- 深色和浅色主题下使用现有 `capClass` 色彩与现有未激活标签样式。

# 公考花生十三技巧 Skill

基于花生十三公开教学体系整理的公务员考试（国考 / 省考 / 联考 / 事业单位）行测 + 申论解题技巧库。覆盖六大模块、二十余题型、上百条速算与解题公式，配真题示例与实战复盘方法。

---

## 一、何时触发

### 强信号（直接进入）

- "公考 / 国考 / 省考 / 联考 / 选调 / 事业单位 / 行测 / 申论"
- "花生十三 / 花生老师"
- 具体题型："资料分析 / 数量关系 / 言语理解 / 判断推理 / 常识判断 / 逻辑填空 / 片段阅读 / 图形推理 / 定义判断 / 类比推理 / 逻辑判断 / 申论大作文 / 公文写作"
- 具体技巧："截位直除 / 415份数 / 假设分配 / ABRX / 中心理解 / 翻译推理 / 加强削弱"
- "行测做题顺序 / 时间分配 / 套题复盘 / 错题归因"
- 用户通过文字或者图片发送题目

## 二、核心工作流

### Step 0：判断是否需要识别具体考情

当用户询问备考计划、套题模拟、考试结构、题量、时长、答题顺序或目标分数时，先确认会实际改变方案的信息：

- 考试年份或预计考试日期；
- 国考、省考、联考、选调、事业单位或其他考试；
- 省份或地区；
- 目标卷型或职位类别，例如国考副省级、市地级、行政执法类，以及地方 A/B/C 类；
- 是否存在公安、金融监管、证监、外语等专业科目；
- 用户是在职还是全职、当前模考水平和每天可用时间。

单题方法与这些信息无关时直接讲题，不增加无意义追问。

具体年份和地区的模块、题量、考试时长、分类方式可能变化。用户问“今年、最新、某省、某类岗位”时，应优先依据用户提供的官方公告/大纲，或使用当前 Agent 的联网搜索能力核验官方来源；本 Skill 中的数字只作为训练示例，不能覆盖官方最新规则。

事业单位考试可能考《职业能力倾向测验》《综合应用能力》《公共基础知识》或当地自定义科目，不得自动套用国考行测申论结构。

### Step 1：识别用户场景

| 用户输入              | 场景    | 进入路径                   |
| ----------------- | ----- | ---------------------- |
| "这道题怎么做" + 题目     | 单题讲解  | Step 2A                |
| "XX 模块怎么学 / 怎么提速" | 模块方法论 | Step 2B                |
| "帮我做一套题 / 套题复盘"   | 套题实战  | Step 2C                |
| "怎么安排备考 / 多久能上岸"  | 备考规划  | Step 2D                |
| "行测怎么分配时间 / 做题顺序" | 策略咨询  | references/strategy.md |

### Step 2A：单题讲解流程

1. **识别题型**：判断属于哪个模块哪个子题型（如"资料分析—增长率比较"）
2. **调用对应 references 文件**：使用运行时提供的 skill 文件读取能力，读取 `references/` 下对应题型文件；不要把相对路径当作用户工作区文件
3. **套用方法**：按"识别标志 → 套公式 / 套方法 → 速算 → 选答案"四步走
4. **给出解析**：包含「题型识别 → 思路 → 计算 → 答案 → 易错点 → 同类题拓展」
5. **附提速技巧**：如果是资料 / 数量，必须给出速算方法（截位直除 / 415 份数 / 假设分配等）

### Step 2B：模块方法论讲解

读取对应 references 文件，按"题型分类 → 核心方法 → 速算 / 速解技巧 → 高频考点 → 易错点 → 真题示例"输出。

### Step 2C：套题实战与复盘

1. 让用户上传 / 粘贴套题（或指定年份真题）
2. 先确认套题的年份、地区、卷型、科目和来源；按该场考试的真实时长建议用户作答
3. 收集用户答案后，逐题讲解错题
4. 输出复盘报告：模块正确率、用时分布、放弃题、薄弱题型、错因分布、改进建议
5. 安排错题无答案重做和同类限时练习，避免只看一遍解析
6. 参考 `references/strategy.md` 的复盘模板

### Step 2D：备考规划

收集：考试类型（国 / 省）、目标岗位、当前水平（模考分数）、剩余时间、每天可投入时长。按"基础 → 强化 → 冲刺"三阶段输出计划，每阶段明确模块重点与刷题量。

## 四、答题顺序与时间分配（核心策略）

答题顺序必须结合目标试卷结构和用户个人模考数据调整。下面只是一种训练起点，不是所有国考、省考和事业单位考试的统一答案。

### 示例顺序（公开经验版）

```
常识（8 min）→ 资料分析（28 min）→ 判断推理（35 min）→ 言语理解（35 min）→ 数量关系（剩余时间选做）
```

### 时间分配原则

1. **先易后难、优先稳定得分模块**：根据用户模考正确率和耗时决定，不预设所有人都必须同一顺序
2. **数量关系重视取舍**：根据目标卷型和用户能力挑选高把握题，不要求全做，也不建议无条件全部放弃
3. **常识不纠结**：会就选，不会就蒙，单题不超过 30 秒
4. **涂卡策略必须在纸笔模考中验证**：可以分模块涂卡，也可以分阶段集中涂卡，以不漏涂、不错位、不挤占最后时间为准

详细策略见 `references/strategy.md`。

## 六、输出规范

### 题目来源标识

讲题、出题或组卷时明确标注来源类型：

- `用户提供`：来自用户上传或粘贴的题目；
- `公开真题`：能够核验年份、地区、卷型和来源 URL；
- `机构参考题/解析`：来自题库或培训机构，答案口径可能存在差异；
- `AI 自编同类题`：用于针对性训练，不是真题、官方样题或押题。

无法核验来源时写“来源待核验”，不要凭题面风格猜测为某年真题。引用公开真题时尽量保留年份、地区、科目、卷型和来源。

### 训练闭环

持续备考任务按需组织为：

1. **限时摸底**：记录模块正确率、耗时、放弃题和做题顺序；
2. **方法学习**：学习一个题型后立即做少量同类题；
3. **专项强化**：针对重复错因和速度瓶颈训练；
4. **模块限时**：形成个人时间目标、跳题标准和取舍策略；
5. **套题模考**：按目标考试真实时长、卷型和纸笔流程完成；
6. **深度复盘**：区分知识、识别、方法、审题、计算、表达和时间问题；
7. **错题重做**：遮住答案重新作答，再安排间隔复习和同类题验证。

不要把刷题数量当成唯一目标。用户只听课不做题时安排即时练习；用户只刷题不复盘时减少新题并先处理错因。

### 纸笔考试训练

目标考试采用纸笔作答时，应提醒用户在中后期使用真实或接近真实的答题卡、申论字数格和考试用品练习：

- 行测填涂速度、错位和漏涂检查；
- 申论手写速度、字数控制、分段和卷面可读性；
- 模拟真实考试时段、休息、饮水和作息；
- 线上练习不能完全替代纸笔套题。

### MindSpace 文件与路径规则

- 普通问答默认直接在对话中输出，不要为了简单讲题强行创建文件。
- 用户明确要求保存错题本、复盘报告、备考计划、练习题集或申论提纲时，使用 `file_write` 创建 Markdown/TXT 文件。
- 最终文件必须写入系统提示中给出的当前 Agent 当日输出目录：`/agents/{当前Agent英文名}/outputs/{系统给出的当天日期}/`。这里的花括号只用于解释规则；实际调用时必须替换为系统提示中的真实 Agent 目录名和真实日期，不能原样写占位符。
- 临时草稿只能写入 `/tmp/{当前Agent英文名}/{系统给出的当天日期}/`，不要把临时路径作为最终交付结果。
- `/skills/huasheng13-skill/` 是只读知识目录，只能读取 `SKILL.md`、`references/` 和 `examples/`，不得把用户成果写进 skill 目录。
- 调用 `file_write` 时使用运行时要求的 `file_path` 和 `content` 参数。创建成功后向用户返回工具给出的虚拟路径。
- 用户要求 Word 或 Excel 且当前 Agent 提供 `office_write` 时：Word 用 `.docx`，学习计划/成绩统计/错题统计用 `.xlsx`；输出仍必须位于当前 Agent 当日输出目录。使用 `office_write` 前按需查看 help，并用结构化 actions 创建，不运行外部 Office 命令。
- 用户要求 PDF 时，当前 skill 没有独立的 PDF 创建工具。可先生成 Markdown 或 DOCX；只有当前 Agent 另有明确可用的 PDF/Pandoc 转换能力时才继续转换，不能声称已经生成 PDF。
- 创建文件并不自动等于生成“成果中心”条目。对话 Agent 的文件由系统运行结束后的产物扫描/注册逻辑处理；skill 只负责写入正确输出目录，不自行操作数据库或伪造 artifact ID。

### 单题讲解输出格式

```
【题型】资料分析—增长率计算
【题干】（用户题目）
【题型识别】关键词"比去年同期增长 X%"→ 增长率计算题
【解题思路】
  1. 定位材料：找到现期量与基期量
  2. 套公式：增长率 =（现期 - 基期）/ 基期
  3. 速算：截位直除（保留前 3 位）
【计算过程】...
```

## 七、使用约束

1. **速算必须给过程**：资料分析、数量关系的题，不能只给答案，必须展示截位直除 / 415 份数等速算过程
2. **方法优先于计算**：先讲识别标志和解题思路，再讲计算
3. **易错点必给**：每道题、每个方法都要附易错点
4. **真题示例用通用数据**：示例题目使用公开真题或自编数据，不照搬任何付费课程原题
5. **申论大作文给框架**：不给完整范文，给"立意 + 结构 + 分论点 + 素材方向"，让用户自己写
6. **备考建议因人而异**：必须先问清用户水平、时间、目标，再给计划，不套模板
7. **图片题先看图**：用户上传截图、图形推理题或材料图片时，使用 `vision_analyze` 理解图片；PDF、Word、Excel、PPT 使用 `document_read`，普通文本使用 `file_read`
8. **时政内容注意时效**：`references/shizheng-redian.md` 只作为知识框架和历史素材。涉及“最新、今年、近期、当前政策/会议/人事”的问题，不得把内置资料当作实时事实；应明确知识截止风险，并在可用时通过知识库或联网检索核验
9. **申论批改使用专项 Skill**：用户提交申论答案并要求打分、找采分点、逐段修改或二次批改时，优先使用已绑定的 `civil-service-essay-grader`；本 Skill 继续负责题型方法、作答思路和训练策略

- 用户要生成 Word 或 Excel → 本 skill 负责公考内容与结构；当前 Agent 有 `office_write` 时生成 DOCX/XLSX，否则输出 Markdown，并说明需要为 Agent 开启“Office 创建编辑”和文件写入权限

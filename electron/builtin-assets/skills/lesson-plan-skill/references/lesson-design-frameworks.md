# Lesson Design Frameworks

Use these frameworks as practical design checks, not as academic decoration.

## Research-Informed Anchors

- UDL: plan multiple ways for learners to engage, access content, and express understanding. Useful for mixed-ability classes, accessibility, and alternative outputs.
- Backward Design / Understanding by Design: start from desired learning results, define acceptable evidence, then plan learning experiences.
- Bloom's taxonomy: balance remember, understand, apply, analyze, evaluate, and create. Do not put every objective at the same low level.
- Formative assessment: gather evidence during learning, not only after teaching. Use quick checks to adjust instruction.
- Differentiated instruction: adapt content, process, product, and support by readiness, interest, and learning profile.

## Backward Design Checklist

1. Desired results
   - What should students explain, solve, perform, write, make, or transfer?
   - Which concepts are enduring and which are only procedural?
2. Evidence
   - What will prove students learned it?
   - Is the evidence visible during class, in worksheet work, oral response, product, or exit ticket?
3. Learning plan
   - What sequence helps students produce that evidence?
   - What misconception will appear, and what teacher move will address it?

## Objective Writing

Good objectives include condition, behavior, content, and quality when useful.

Examples:

- Instead of "理解一次函数", write "能根据表格和图像解释一次函数中斜率与截距的意义，并用一个生活情境说明变化关系".
- Instead of "掌握文章主旨", write "能用两句话概括文章主要观点，并从文本中找出两处证据支持判断".
- Instead of "培养合作能力", write "能在小组实验中分工记录变量、观察现象，并用数据说明结论".

## Activity-Evidence Alignment

Each major activity should map to one objective and one evidence point.

| Objective type | Better evidence |
| --- | --- |
| Remember | quick recall, matching, label diagram |
| Understand | explain in own words, compare, give example |
| Apply | solve a new problem, complete procedure |
| Analyze | find pattern, classify causes, diagnose error |
| Evaluate | justify choice, critique solution, defend argument |
| Create | design product, write plan, build model, present |

## Public Lesson / Demo Lesson

Strengthen these parts:

- one clear learning problem or driving question;
- visible student thinking, not only teacher explanation;
- staged questions from accessible to challenging;
- board/slides that reveal structure gradually;
- one or two high-quality student products or responses;
- fallback plan if students cannot answer as expected.

Avoid:

- too many activities without enough thinking time;
- over-scripted student answers;
- visual polish that hides weak objective-evidence alignment.

# HTML Visual Standards

The HTML artifact should feel like a study object, not a generic web page.

## Layout

- Put the concept card and the visual on the first screen.
- Use one main visual stage.
- Keep controls close to the visual they affect.
- Use a compact practice section below the visual.
- Make mobile layout single-column.

## Visual Tone

Prefer:

- quiet high-contrast surfaces;
- clear axes, labels, and callouts;
- restrained color palette with one primary and one contrast color;
- small-radius cards;
- functional controls.

Avoid:

- decorative gradient blobs, orbs, bokeh, and generic hero layouts;
- huge marketing headings;
- nested cards inside cards;
- excessive animation that does not explain anything;
- long text blocks before the visual.

## Motion

Motion should show sequence, causality, change, or attention.

Good uses:

- step-by-step reveal;
- replay/reset;
- slider updates;
- drawing a connection after the related objects appear;
- moving a point along a curve.

Weak uses:

- pulsing every element;
- decorative floating shapes;
- transitions that slow study.

## Controls

Use controls only when they improve learning:

- `Next step` for segmented explanations.
- `Reset` for replay.
- `Range` slider for a meaningful parameter.
- Toggle for comparing two states.

Every control must visibly change the artifact.

## Text

- Labels should sit near what they describe.
- Use concise captions.
- Wrap long Chinese labels.
- Keep formula text readable.
- Do not let text overlap visual marks.

## Accessibility

- Use semantic headings.
- Keep contrast high.
- Do not rely on color alone; pair color with labels or shape.
- Ensure buttons have visible text.

## Validation Checklist

Before delivering:

- First screen shows the concept and visual.
- Controls work.
- Text does not overlap.
- Visual is understandable without a long intro.
- Practice prompts are visible.
- File is self-contained and opens directly in a browser.

# 408 可视化模板 UI 规范

这些模板用于学习和复习，不是营销页。目标是让用户快速看懂机制、跟随步骤、迁移到纸笔考试。

## 设计定位

- 做成“学习工作台”，不是普通文章页，也不是夸张大屏。
- 首屏必须直接呈现可视化主体，不要用大段说明占首屏。
- 信息密度要高，但层级清晰：标题 -> 当前步骤 -> 主画布 -> 状态表 -> 考试提示。
- 视觉风格要专业、克制、稳定；动画只服务理解，不做纯装饰。

## 页面结构

默认采用四区布局：

1. **Top bar**：主题、科目、题型、复杂度/算法/规则。
2. **Main visual**：图、表、状态机、数据通路、队列或矩阵。
3. **Step inspector**：当前步骤、解释、公式、伪代码或寄存器/变量。
4. **Exam transfer panel**：手算表格、易错点、quick check。

移动端改为单列，但顺序不变：标题 -> 可视化 -> 控制 -> 步骤解释 -> 状态表。

## 控制区

可交互模板至少包含：

- 上一步；
- 下一步；
- 重置；
- 播放/暂停；
- 长流程需要速度控制；
- 当前步骤计数，例如 `STEP 3 / 12`。

按钮要稳定尺寸，点击后不导致布局跳动。长文本不要放进按钮。

## 视觉语言

- 使用 8px 或更小圆角。
- 不要卡片套卡片；主区域、侧栏、底部表格是并列面板。
- 颜色按含义使用，而不是装饰：
  - 蓝/紫：CPU、控制、抽象机制；
  - 绿：正确、命中、完成、可运行；
  - 橙/黄：当前步骤、活跃状态、等待；
  - 红：缺页、错误、冲突、阻塞、丢弃。
- 背景应接近白色或浅灰，不使用大面积渐变和装饰光斑。
- 表格行高、单元格宽度要稳定，数据变化不能造成大幅抖动。

## 教学可读性

每一步必须同步更新：

- 主画布状态；
- 侧栏解释；
- 状态表/矩阵；
- 考试书写提示。

不要只展示动画。对 408/期末复习，必须保留“纸笔可写”的过程表。

## 交互细节

- 状态变化应有轻量 transition，但不要依赖动画才能理解。
- 所有关键状态必须通过文本/表格可读，不能只靠颜色。
- 图中标签必须短，详细解释放侧栏。
- 适配 1366x768、1920x1080 和移动端宽度。
- 字号不要随 viewport 缩放；移动端通过布局换行解决。

## 模板生成要求

当从 starter template 改造时：

1. 保留整体四区布局。
2. 替换 `DATA` 对象，不要硬编码到 DOM 里。
3. 保留步骤控制。
4. 保留状态表或矩阵表。
5. 保留考试迁移说明。
6. 如果题目更适合静态图，也要给出步骤表，不要只给一张图。
